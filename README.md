# Atlas + ESP32 气压障碍检测实验台

工程由两部分组成：

- `main/`：ESP-IDF 6.0.2、ESP32-S3。读取5个SDP3x，通过无线透明串口向Atlas发送实时数据，并执行Atlas下发的滑台和模拟数据命令。
- `atlas/`：运行在Huawei Atlas 200I DK A2。统一负责无线串口、滑台控制、批量采集、CSV、同条件图像、实时推理和有线网页。
- `web/`：旧的ESP32 USB诊断页面，仅保留为开发备用，正式实验不再使用。
- `training/`：电脑端训练脚本，把完整实验CSV分组训练轻量压力斜坡CNN并导出ONNX。

## ESP32 WiFi直接采集

当前固件同时保留两条链路：

- ESP32-S3建立WiFi热点并在板内托管采集网页，电脑无需USB串口即可接收200 Hz压力、控制滑台和下载CSV。SDP3x采用最早固件的`0x3615`连续测量方式，在相邻读取之间由传感器内部平均；ESP32随后应用单向卡尔曼滤波，默认`Q=0.03 Pa²、R=0.02 Pa²`。
- Atlas继续使用原有UART透明传输模块；Atlas没有无线网卡也不影响这条串口推理链路。

烧录后，电脑连接：

```text
WiFi名称：DronePressure
WiFi密码：pressure123
网页地址：http://192.168.4.1
```

网页包含实时压力、自动批量实验、滑台参数、模拟数据和实验参数方案。批次结束或停止后，浏览器会下载兼容训练脚本的CSV。参数方案保存在当前浏览器的`localStorage`中。

热点名称、密码和信道可在`idf.py menuconfig`的`Drone controller -> ESP32 WiFi collection page`中修改。密码少于8个字符时热点会变为开放网络。

WiFi采集与Atlas串口控制不能同时操作滑台。使用ESP32网页采集时，应停止Atlas服务或断开Atlas侧透明串口接收端；完成采集后再恢复Atlas推理链路。

如果要求ESP32通过WiFi直接把数据发送给Atlas，则Atlas必须额外增加受其Linux内核支持的USB无线网卡，或者使用具有无线客户端/网桥功能的路由器转成以太网。仅修改ESP32固件无法让没有无线接口的Atlas直接接收WiFi。

## 距离缓启停与首次回起点（2026-08-30）

ESP32 WiFi网页、Atlas网页及备用USB网页的缓启动/缓停止参数均改为 **mm**，基线等待、终点停留、实验间隔仍为 **ms**。采样、滤波、接线和方向极性不变。

- 默认测量：起点10 mm、终点1900 mm、速度1500 mm/s、缓起225 mm、缓停75 mm。
- 默认复位：速度1000 mm/s、缓起150 mm、缓停150 mm。
- 正向测量的缓起区为10～235 mm，缓停区为1825～1900 mm；改变速度不会改变这两个距离区间。反向时按运动方向从出发点/目标点计算距离。
- 短行程不足以容纳两个缓冲区时，固件取加速和减速速度上限中的较低值，自动降低峰值速度形成三角速度曲线；不会压缩缓起距离强行冲到设定速度。距离为0表示关闭该侧缓冲。位置分辨率由脉冲当量决定，80 pulse/mm对应0.0125 mm。
- 修复第一次0→10 mm短行程漏掉“运动中”状态后一直等起点的问题：改用命令确认后新收到的、未锁定且已使能的静止到位状态；停止后也等待新状态再清除锁定。断流/掉线不会被当作到位。网页位置仍是已发脉冲推算值，不是编码器实测。

更新步骤：

1. 结束当前实验，按项目原来的ESP-IDF烧录流程更新ESP32；`build/Drone.bin`为本次编译的应用固件，不是从0地址烧录的整片合并镜像。
2. WiFi采集网页随固件更新。重新打开`http://192.168.4.1`并按Ctrl+F5，确认缓启停旁单位为mm。
3. 使用Atlas网页时，同步更新`atlas/service.py`、`atlas/protocol.py`、`atlas/web/`并重启服务，再刷新网页。不要同时用WiFi页面和Atlas控制运动。
4. 旧参数方案载入时按原速度和脉冲当量由ms换算为mm，请核对并重新保存。新方案带`ramp_unit: "mm"`，不会重复换算；如需上面的整值默认参数，请手动填写225/75/150/150。

兼容性：旧文本`MOVE`及二进制`0x11`仍按ms解释；新文本指令为`MOVE_MM 目标mm 速度mm/s 缓起mm 缓停mm`，新二进制命令`0x16`的负载为`<iIII>`（目标µm、速度µm/s、缓起µm、缓停µm）。新网页/服务不会把mm参数发给旧ms命令；旧固件不支持新命令，需要先升级固件。

新采集CSV版本为5，缓启停列改为`accel_mm`、`decel_mm`；旧CSV不改写。这里保存的是指定的测量缓冲距离，短行程的实际速度轮廓受上述三角曲线规则约束。

| 参数 | 默认值 |

| 透明串口 | UART1，TX GPIO17、RX GPIO18、115200 baud |
| P100S控制方式 | 脉冲 + 方向 |
| 脉冲+ / 脉冲- / 方向+ / 方向- | GPIO4 / GPIO5 / GPIO6 / GPIO7 |
| 一圈指令脉冲 | 10000 |
| 一圈滑台位移 | 125 mm |
| 换算 | 80 pulse/mm |
| 总行程 | 2000 mm，可在 ESP32采集网页独立修改 |
| 默认测量速度 / 固件硬上限 | 1500 / 2000 mm/s（最大2 m/s） |
| 1.5 m/s对应指令频率 | 120000 pulse/s |
| 1.5 m/s对应电机转速 | 约720 rpm |
| 2 m/s对应指令频率 / 电机转速 | 160000 pulse/s / 约960 rpm |
| 通信看门狗 | 1000 ms |

当前固件恢复五传感器模式，五个同地址SDP3x分别连接到TCA9548A通道0～4，TCA主总线连接GPIO1/2。根据现场确认和逻辑分析仪采样，P100S控制端采用脉冲+、脉冲-、方向+、方向-四根3.3V信号线，ESP32按下表直接输出对应信号。

GPIO和方向极性都是可修改的软件默认值。若实际正反方向与界面相反，只需在`menuconfig`中切换`Invert motion direction`，无需改动接线。

## 完整接线方式

整体连接关系：

```text
5个SDP3x ── TCA9548A ── GPIO1/2 I2C ── ESP32-S3
                                             │
                                             ├── UART ── 无线透明传输模块 )))) USB串口接收端 ── Atlas 200I DK A2
                                             │
                                             └── GPIO4/5/6/7 ── 3.3V四线信号 ── P100S ── 滑台电机

电脑 ── 有线网络 ── Atlas一体化实验与推理网页
```

### ESP32与单个SDP3x（调试备用，默认关闭）

| ESP32-S3 | SDP3x | 说明 |
|---|---|---|
| 3.3V | VCC | 使用3.3V供电 |
| GND | GND | 必须共地 |
| GPIO1 | SDA | I2C数据线 |
| GPIO2 | SCL | I2C时钟线 |

只有在`menuconfig`中启用`Direct single-sensor debug mode`时才使用该接线；正式五路固件不要这样连接。

### ESP32与TCA9548A（当前默认）

| ESP32-S3 | TCA9548A | 说明 |
|---|---|---|
| 3.3V | VCC | 只使用3.3V逻辑电源 |
| GND | GND | 传感器侧公共地 |
| GPIO1 | SDA | I2C数据线；新版固件启动时读取电平并扫描复用器地址 |
| GPIO2 | SCL | I2C时钟线；新版固件启动时读取电平并扫描复用器地址 |

TCA9548A主总线的SDA、SCL需要上拉到3.3V。若所用模块已经带有上拉电阻，不要再并联过多上拉；若没有，可先使用约4.7 kΩ上拉电阻。

### 五个SDP3x传感器（当前默认）

五个传感器地址相同，因此必须分别连接到TCA9548A的不同通道：

| 传感器 | TCA9548A通道 | 数据线连接 |
|---|---:|---|
| SDP3x-1 | 0 | SDA→SD0，SCL→SC0 |
| SDP3x-2 | 1 | SDA→SD1，SCL→SC1 |
| SDP3x-3 | 2 | SDA→SD2，SCL→SC2 |
| SDP3x-4 | 3 | SDA→SD3，SCL→SC3 |
| SDP3x-5 | 4 | SDA→SD4，SCL→SC4 |

所有传感器VCC接3.3V、GND接传感器侧公共地。若使用的SDP3x转接板标注了不同供电范围，应以转接板说明为准；不要把5V直接接入ESP32的I2C引脚。未连接传感器时，可在Atlas网页开启“ESP32模拟数据”完成整条链路测试。

### ESP32与无线透明串口模块

| ESP32-S3 | 无线模块ESP32端 | 说明 |
|---|---|---|
| GPIO17（TX） | RX | 交叉连接 |
| GPIO18（RX） | TX | 交叉连接 |
| GND | GND | 必须共地 |
| 合适电源 | VCC | 必须按模块额定电压供电 |

两端统一设置为`115200 baud、8 data bits、no parity、1 stop bit、无流控`。无线模块只工作在双向透明传输模式，不使用Wi-Fi协议。若模块串口是5V电平，必须增加电平转换，不能直接连接ESP32的3.3V RX引脚。

无线链路另一端使用USB串口接收模块，直接插入Atlas USB口。Atlas中通常显示为`/dev/ttyUSB0`，可通过以下命令确认：

```bash
ls -l /dev/ttyUSB*
```

### ESP32与P100S

根据实测接线，P100S控制端使用3.3V四线信号，默认连接如下：

| ESP32-S3 | P100S侧 | 固件行为 |
|---|---|---|
| GPIO4 | 脉冲+ | 3.3V脉冲正相信号，空闲为高 |
| GPIO5 | 脉冲- | 与脉冲+严格互补，空闲为低 |
| GPIO6 | 方向+ | 前进为低、反向为高，换向后等待20ms再发脉冲 |
| GPIO7 | 方向- | 运动期间固定低电平 |

逻辑分析仪CSV中通道8～11依次接入脉冲+、脉冲-、方向+、方向-：脉冲两路同步反相翻转，方向+保持低，方向-负责换向。固件按该波形实现。`ENABLE`只保留为软件状态，不再占用GPIO。可在`idf.py menuconfig -> Drone controller`中核对：

- `Pulse+ GPIO = 4`
- `Pulse- GPIO = 5`
- `Direction+ GPIO = 6`
- `Direction- GPIO = 7`
- `Invert Direction- output`
- `Enable output active-low`

初次联调时应先让滑台脱离危险区域，以低速、5～10 mm短距离测试方向。驱动器主电源、电机动力线、保护接地和制动电阻属于高压/大功率接线，应由具备相应资质的人员按照P100S原厂资料完成，本工程不定义这些端子的连接方式。

### Atlas与电脑

- 无线接收端：插入Atlas USB口，作为`/dev/ttyUSB*`串口。
- Atlas与电脑：通过网线接入同一局域网。
- Atlas一体化网页：访问`http://Atlas有线IP:8080`，完成采集、运动、绘图和推理。
- 电脑不再连接ESP32 USB；ESP32原生USB只作为开发调试备用。
- 不需要用Wi-Fi传输传感器数据或滑台命令。

上电建议顺序：先保持P100S使能关闭，启动ESP32和无线链路，再启动Atlas服务并确认网页显示“串口在线”；最后在低速短距离条件下解除停止锁定并使能滑台。

## 通信与安全状态机

无线模块只做双向透明串口，不使用Wi-Fi。链路采用小端二进制帧：

`0xA55A + version + type + sequence + payload_length + payload + CRC16`

遥测包含五路压力/温度/有效位、滑台相对位置、软件限位、剩余脉冲和运动状态。Atlas接收遥测并发送安全心跳、滑台配置、运动、停止、使能和测试模式命令；所有正式采集由Atlas后台执行。

新版固件每秒2次上报各传感器的诊断状态、累计错误数和底层ESP错误码，Atlas实时压力卡片会直接显示原因：

| 诊断码 | 含义 | 优先检查 |
|---:|---|---|
| 1 | TCA9548A通道选择失败 | TCA9548A供电、SDA/SCL、地址0x70及公共地 |
| 2 | SDP3x连续测量启动失败 | 对应TCA通道、传感器供电、地址0x21 |
| 3 | SDP3x读取失败 | 对应通道接线、I2C上拉和传感器状态 |
| 4 | 压力CRC错误 | I2C干扰、线长、上拉和时钟频率 |
| 5 | 温度CRC错误 | I2C干扰、线长、上拉和时钟频率 |
| 6 | 比例因子CRC错误 | I2C干扰、线长、上拉和时钟频率 |
| 7 | 比例因子为0 | 传感器响应内容异常或型号/命令不匹配 |
| 8 | 扫描0x70～0x77未发现TCA9548A | 主线接线、供电、复位脚或器件故障 |
| 9 | SDA被拉低 | SDA短路、接反或从设备锁死总线 |
| 10 | SCL被拉低 | SCL短路、接反或从设备锁死总线 |
| 11 | SDA和SCL均被拉低 | 主线短路、无上拉或TCA未供电 |

固件启动时会扫描`0x70～0x77`，找到TCA9548A后自动采用实际地址，不再要求地址焊盘必须为`0x70`。传感器读取失败时压力和温度会清零，不再把上一次成功读数伪装成当前值。USB监视器中的`sdp3x`日志也会输出通道号、诊断码、ESP错误名称和累计次数。必须同时部署新版ESP32固件和新版Atlas目录，旧固件只会显示“未提供诊断”。

Atlas每200 ms发送心跳。ESP32超过1秒未收到心跳会停止后续脉冲、关闭使能并锁定软件停止；滑台目标超出软件限位或速度超限时拒绝执行。RMT按当前频率动态分块，兼顾高速连续性和停止响应。

系统没有原点传感器、物理限位和硬件急停。ESP32每次上电只能把当时位置视为相对0 mm，软件位置无法发现失步、打滑和错误启动位置，不能视为机械绝对安全保护。

## ESP32构建

```text
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
idf.py flash
```

配置位于 `Drone controller` 菜单，包括传感器、滤波、透明串口、P100S GPIO、方向/使能极性、最大脉冲频率和1秒看门狗。默认完整固件已使用 ESP-IDF 6.0.2 编译通过，生成文件为 `build/Drone.bin`。

## Atlas启动

参见 [atlas/README.md](atlas/README.md)。最简启动方式：

```bash
cd atlas
python3 -m pip install -r requirements.txt
./run.sh --host 0.0.0.0 --port 8080
```

电脑通过有线网络访问 `http://Atlas地址:8080`。网页集成实时压力、推理、滑台、缓启停、批量实验、模拟数据、图像预览和文件下载。每批CSV、同名批次SVG及同条件对比SVG保存在`atlas/data/`。

45° RPLIDAR参考程序的采样/决策状态机和独立采集入口位于`atlas/lidar_workflow.py`、`atlas/lidar_capture.py`。它按完整扫描圈而不是GUI刷新帧进入采样，完成预热、数据质量门槛和冻结快照后才进入决策；具体运行和ROI标定方式见[Atlas说明](atlas/README.md#45-rplidar采样与决策入口)。参考文件本身没有陀螺仪数据，真正IMU触发可使用其中的`StableAngleGate`适配。

## 旧ESP32 USB诊断网页

Windows进入工程根目录，使用本机HTTP服务打开网页：

```powershell
python -m http.server 8000
```

该页面仅用于没有Atlas时的开发诊断。正式实验直接访问Atlas，不需要启动本地HTTP服务，也不需要电脑连接ESP32。

旧页面仍可在Chrome或Edge访问`http://localhost:8000/web/`，功能包括：

- 设置实验条件、批次、真实标签、障碍距离、速度和备注；
- 自动执行1～500次独立实验：正向运动采集，反向运动只复位；
- 分别设置测量和复位的速度、缓启动距离、缓停止距离、基线等待及实验间隔；
- 使用Chrome/Edge文件接口把CSV持续写盘，中途停止也保留已写入数据；
- 完成本轮后暂停/继续，或立即执行软件停止；
- 统计采样帧和串口丢帧；
- 设置2 m行程、80 pulse/mm、软限位及手动运动；
- 启用无传感器模拟数据；
- 按`trial_id`保存降采样预览，将同一条件的每次独立实验叠加并导出PNG。

点击“选择CSV并开始批量实验”后先选择保存位置；页面随后自动运行。一个批次内不要改变障碍物状态：无障碍和有障碍应分别采集为不同CSV。每一行带有`batch_id`、`trial_id`、`trial_index`和`phase=measure`。浏览器缓存只用于看图，训练始终使用原始CSV；模拟CSV包含`sensor_test_mode=1`，训练脚本会自动排除。

## 电脑训练与Atlas部署

参见[training/README.md](training/README.md)。默认训练方法自动定位每次实验末端的快速下降，只用下降之前的历史窗口学习“平台后期向上斜坡”，不会把后续下降泄漏给模型。脚本先按`trial_id`拆出每次正向实验，再以整份批次CSV为单位划分训练、验证和测试集，确保同一批次的相近实验不会泄漏到不同集合。

电脑训练输出`pressure_ramp.onnx`和概率阈值；使用ATC转换为`pressure_ramp.om`后放入`atlas/models/`。Atlas通过`ais_bench`加载OM进行实时推理；模型未启用或加载失败时保留CPU/LIF规则回退以便联调。

正式验收指标应是整次扫描的障碍召回率、每次扫描误报数以及在末端急速下降前的提前报警时间，而不是随机采样点准确率。
